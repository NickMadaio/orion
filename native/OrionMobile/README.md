# Orion phone

Open `OrionMobile.xcodeproj` in Xcode, select **OrionPhone** and an iPhone
Simulator, then Run. This is a real SwiftUI app target linked to the existing
MobileCore package. It needs no paid developer account for Simulator.

Today opens disconnected. **Explore a sample day** displays an explicitly
labeled example generated by the same TodayPlanScheduler used by the Mac.
Plan shows its timeline. The sample uses a fixed Wednesday, 9 September 2026,
at 11:00 London time; it is not a reading of the device's current day. Close
sample clears it, and terminating/relaunching starts disconnected again.

The five tabs match the mobile foundation: Today, Plan, ORION, Health, Control.
Conversation, Health and Control describe their missing connections. There is
no production pairing, account, health access, push registration or remote
execution in this build. A Simulator-only read client is described below. No personal data is loaded or written. The existing
Mac application and its saved plan are unaffected.

From the repository root:

```bash
scripts/orion_v2_phone_check.sh
# Or choose an available iPhone Simulator by UDID:
scripts/orion_v2_phone_check.sh 98256948-7A0B-4AE9-9928-8ED1A66C971F
```

The check builds and installs into Simulator, exercises the disconnected and
sample routes, verifies relaunch and dismissal, and keeps screenshots in the
Xcode test result under `.builds/phone-shell-check/Logs/Test/`. Xcode is selected
per command; the machine's global developer-directory setting is unchanged.

Read `App/OrionMobileApp.swift` for the screen and `AppUITests/PhoneShellTests.swift`
for the normal-route check. `Sources/MobileCore/` remains platform-independent.
`scripts/orion_v2_mobile_check.sh` still checks that library separately.

This establishes the Simulator-shell portion of REC-USABLE-CLIENT, associated
with Phases 16 and 19. The recovery gate remains open: an authenticated read-only
Today route, ownership, stale/offline recovery and a durable service come next.
Physical-device signing, biometric, notification and lost-device proof are
separate from these Simulator results.

## Simulator read-only service check — 15 September

Run `python3 scripts/orion_v2_phone_read_check.py` from the repository root.
This builds the app and exporter, starts the actual loopback adapter against a
private disposable SQLite store, and runs both phone UI scenarios. The connection
scenario uses a synthetic plan: it verifies stale display, a service outage,
recovery and clearing the reading after access revocation. It does not load your
personal plan. Logs and XCTest screenshots live in `.builds/phone-read-check/`.
The script removes its temporary credential from the app's current data container
and closes the server when it finishes. It refuses to overwrite an existing
bootstrap. No service stays enabled.

The app's `--local-today` bootstrap is compiled only for Simulator. It accepts a
loopback port, expected owner and short-lived harness token from a development
file. It is not physical-device pairing or production sign-in. Normal launches
remain disconnected and support the original sample route. The reader uses an
ephemeral bounded URLSession and refuses redirects, wrong owners, invalid plans,
older revisions and changed content at the same revision. It remembers revision
evidence even after refusing a response. It retains the last reading with an
unavailable warning on a transport/service failure and clears it on 401 or an
unverifiable response. Plan age is recomputed on-screen every ten seconds.

`TodayPlanExport` accepts an explicit saved-plan path, validates the current plan
using MobileCore, and emits a bounded read envelope. It never edits the input.
There is no automatic publisher or personal-data connection yet. Its `--fixture`
mode produces synthetic data for the check. Snapshot capture uses the original
plan's generation time, so exporting old data cannot make it recent.

Core contract regressions: `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer
swift test --package-path native/OrionMobile --filter TodayReadTests` (one shell
command). Actual redirect/oversized-response transport experiments, persistent
account storage, TLS and physical-device access remain unproven.

## Preview your accepted Mac plan locally

From the repo root:

```bash
python3 scripts/orion_phone_preview.py --source "$HOME/.openclaw/orion-controlled/today-plan.json"
```

This opens a five-minute, read-only Simulator preview of that explicit file.
Use `--seconds 60` for one minute, or `--verify` to run the UI check and exit.
Relative source paths resolve from your calling directory. No daemon or public
listener is installed. The temporary session, database copy and Simulator access
file are removed when the command exits normally, on timeout, or on Ctrl-C.

Each refresh validates the configured file through TodayPlanExport and publishes
its accepted revision. Unreadable, invalid or rolled-back sources refuse the read
while preserving the previous database snapshot. Only the configured owner can
trigger export. The command never accepts a new plan or edits Calendar/Reminders.
An old accepted plan remains marked stale; this is not a live calendar refresh.
Physical-phone pairing and production account access remain separate work.

## Persistent device identity

Control now shows the device key’s public fingerprint and whether it is paired.
The app creates an EC P-256 private key in the platform Keychain, then reloads
its reference on later launches. Only the public key is exported to compute the
fingerprint. A lookup error never silently replaces an existing identity.

Simulator keys are software-backed and explicitly labeled that way. The physical
iPhone code requires Secure Enclave with WhenUnlockedThisDeviceOnly access and
no software fallback. That path compiles, but has not run on a physical iPhone.
The local verification button signs a fresh challenge and checks both a valid
signature and rejection of a changed challenge. It proves local key possession;
it does not authenticate an account or approve a remote action.

Simulator build commands now use normal ad-hoc signing so Xcode supplies the
Simulator entitlements needed for Keychain. This needs no paid account and does
not change the installed Mac application's identity or permissions. The device
key intentionally survives app relaunch; temporary read-session files are still
cleaned up by the preview harness. Uninstalling an app is not a promise that its
Simulator Keychain item is removed. No identity reset or deletion is automated.

Run `scripts/orion_v2_phone_check.sh` for sample and identity UI verification, or
`python3 scripts/orion_v2_phone_read_check.py` for identity plus the complete local
read/recovery scenario. See `PhoneDeviceIdentity` in `App/OrionMobileApp.swift`
and `testDeviceIdentitySurvivesRelaunch` in `AppUITests/PhoneShellTests.swift`.
