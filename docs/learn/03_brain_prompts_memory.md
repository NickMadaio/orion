## 1. OpenClaw: the gateway and how ORION is configured on it

### 1.1 What OpenClaw is

- **What it is** — OpenClaw is a third-party agent runtime (npm package `openclaw`, version `2026.7.1-2` in this install; `package.json` of the bundled copy says so). It runs a long-lived local "gateway" process, owns the model providers (Anthropic cloud, Ollama local), builds the system prompt for every agent turn from workspace files, exposes tools, loads plugins, runs cron jobs, indexes memory, and writes session transcripts. ORION is not a fork of it. ORION is (a) a **plugin** (`orion-control`, TypeScript, registers the typed-action tools and hooks), (b) a **workspace** of prompt files OpenClaw injects, (c) a pile of **scripts** (`scripts/orion-*`) the model runs through an allowlisted `exec` tool, and (d) **front ends** (the native Mac app, the iPhone app, the `orion-remote` transport) that call `openclaw agent --session-key …` as a subprocess. See `AGENTS.md` (repo root) and `MEMORY.md:13-15`: "The active runtime is OpenClaw plus the native app and `orion-control`; the older Python package is not the implementation path."
- **Where** — Binary shim `~/.openclaw/bin/openclaw` → bundled Node (`~/.openclaw/tools/node-v24.15.0/bin/node`) → `~/.openclaw/tools/node-v24.15.0/lib/node_modules/openclaw/dist/entry.js`. Config: `~/.openclaw/openclaw.json`. Workspace: `~/.openclaw/workspace/`. State: `~/.openclaw/state/openclaw.sqlite`, `~/.openclaw/agents/main/{agent,sessions}`.
- **Why a gateway at all** — the Mac app and the phone link both start `openclaw agent` as a subprocess (`native/Orion/Sources/Orion/GatewayClient.swift:115-134`, `scripts/orion-remote` `askBrainOnce`), and the gateway is the long-lived process that keeps plugins loaded, models warm and cron running.

### 1.2 Process and install

- launchd job `~/Library/LaunchAgents/ai.openclaw.gateway.plist` (label `ai.openclaw.gateway`): `KeepAlive true`, `RunAtLoad true`, runs `node …/openclaw/dist/index.js gateway --port 18789` through a wrapper `~/.openclaw/service-env/ai.openclaw.gateway-env-wrapper.sh` that loads an env file from the same directory (contents not read; may hold secrets). Stdout goes to `~/Library/Logs/openclaw/gateway.log`, stderr to `/dev/null`.
- Other launchd jobs in the same folder that belong to ORION (not the gateway): `com.nickmadaio.orion.remote` (the `orion-remote` transport), `.tts`, `.voiceid`, `.dashboard`.
- The plugin is installed by copying its build output to `~/.openclaw/extensions/orion-control/` (contains `dist/`, `openclaw.plugin.json`, `node_modules`, `README.md`, `CAPABILITY_TIERS.md`; the installed `openclaw.plugin.json` was last written 2026-10-13 02:10). OpenClaw also keeps a generation cache `~/.openclaw/npm/projects/openclaw-plugin-orion-control__openclaw-generation__g-…` **(inferred: a build cache; not read)**.
- **Important consequence:** editing `plugin/orion-control/src/*.ts` changes nothing live until it is built (`npm run build` in `plugin/orion-control`) and installed into `~/.openclaw/extensions/orion-control`, and the gateway restarts. Likewise `plugin/workspace/*.md` changes nothing live until synced (§2.1).

### 1.4 Plugin registration

- **What it is** — The plugin tells OpenClaw about itself through two files: a manifest `plugin/orion-control/openclaw.plugin.json` and a code entry `dist/index.js` (`package.json` → `"openclaw": {"extensions": ["./dist/index.js"]}`).
- **Where** — `plugin/orion-control/openclaw.plugin.json:2` (`"id": "orion-control"`, version `0.13.0`), `:6` (`configSchema`, 63 properties), `:256` (`activation: {onStartup: true}`), `:259` (`contracts.tools`), `:270` (`toolMetadata`, every tool `optional: true`). Code: `plugin/orion-control/src/index.ts:1103` `defineToolPlugin({…})`; the seven tools are declared at `:1111` `orion_task_run`, `:1229` `orion_tool_propose`, `:1290` `orion_tool_list`, `:1319` `orion_tool_run`, `:1348` `orion_task_status`, `:1359` `orion_permission_status`, `:1436` `orion_permission_change`.
- **How it works** — At gateway start, OpenClaw loads `dist/index.js`, validates the plugin's `config` from `openclaw.json` against `configSchema` (so a flag missing from the manifest is rejected — a test, `manifest.test.ts`, keeps manifest and runtime config in parity: `MEMORY.md:34-36`), and calls `register`. ORION wraps `register` so provenance hooks are installed first:

```ts
// plugin/orion-control/src/index.ts:1739-1746
// `defineToolPlugin` has no hook seam, so compose one around its register step.
const baseRegister = entry.register;
entry.register = (api: unknown) => {
  installProvenanceHooks(api as ProvenanceHostApi);
  return baseRegister?.(api as never);
};
```

  `installProvenanceHooks` (`:1528`) registers these OpenClaw hooks: `message_received` (record the channel message), `llm_input` (record the agent prompt), `after_tool_call` (record untrusted tool results for taint checks), `before_tool_call` (the repeat-call guard and gate), `agent_end`; then conditionally `registerAccountHealth` (`:1663`), `registerLocalRouting` (`:1673`, when `localRouting` is `shadow` or `on`) and a `before_agent_finalize` hook for episodic capture (`:1688`, when `enableEpisodicCapture`). None of the hooks in `index.ts` inject prompt text. The prompt-injecting hooks are in `local-routing.ts` and `account-health.ts` (§5.6).
- **Contracts** — Hook names the host provides (seen in the code): `message_received`, `llm_input`, `before_prompt_build` (returns `{systemPrompt?, appendContext?}`), `before_agent_reply` (returns `{handled, reply}`), `before_agent_finalize` (returns `{action:"revise", retry:{instruction,…}}`), `reply_payload_sending`, `before_tool_call`, `after_tool_call`, `agent_end`.
- **History** — `ceb6b79` 2026-09-15: `openclaw-plugins/` and `openclaw-workspace/` folded into `plugin/`. Version 0.13.0 is the manifest's number.
- **Gotchas** — (1) The plugin and the workspace are separately deployed: a green `vitest` run proves nothing about what the gateway loads. (2) `before_prompt_build` with `systemPrompt` **replaces** the whole system prompt for that turn (that is how local routing swaps the 17k-token workspace prompt for a 2k-token one, `b4c8b55`).

### 1.5 Cron jobs (by structure)

- OpenClaw has its own cron store (jobs are not in `openclaw.json`; they live in OpenClaw state **(inferred: `~/.openclaw/state/openclaw.sqlite`; not opened)**). The CLI `openclaw cron list|disable` manages them (see `scripts/orion_v2_lock_check.sh:56-67` which stubs the CLI with three jobs).
- Known ORION jobs, by name: `orion-focus-guard` (runs `orion-focus check` every minute), `orion-standing-orders`, `orion-daily-memory` (nightly: `orion-daily` summary, then a memory re-index; `scripts/orion-setup:391-406` — "OpenClaw owns the one nightly pipeline: summary, then memory index").
- Delivery: cron `announce` hands output to a chat channel, and this gateway has **no** chat channel installed, so output used to evaporate (`scripts/orion-cron-deliver:3-25`). `orion-cron-deliver` wraps a command, applies `--match` (only deliver matters), de-duplication and a per-label rate limit, then posts through `orion-discord-alert` (a webhook, not a bot token). State: `~/.openclaw/orion-controlled/cron-delivery.json` (last message per label: keys `focus-guard`, `daily-memory`) and `cron-delivery-history.jsonl` (1.5 MB at snapshot; rows `{v, at, label, outcome, exitCode}`).
- Walk-through of the nightly memory pipeline is in §6.4.

### 1.6 Channels

- `openclaw.json` has no `channels` key, and `scripts/orion-cron-deliver` says `openclaw channels list` returns "no configured chat channels". So "channel" in the OpenClaw sense does not exist here. ORION's inbound surfaces are instead:
  - the **Mac app** → `openclaw agent --session-key orion-app-v2 --message … --json --timeout N [--model M] --thinking L` (`GatewayClient.swift:53,115-134`);
  - the **iPhone app** and **Discord**, via the `orion-remote` transport, which calls the same CLI with `--session-key $BRAIN_SESSION --message-file <tmp file> --json` (`scripts/orion-remote` `askBrainOnce`, around line 800);
  - voice, through the app (speech → text → the first path).
- `session.dmScope: per-channel-peer` is therefore mostly inert (one peer). The `Authorized Senders`/`Messaging` sections of OpenClaw's own system prompt still exist but are not ORION's concern **(inferred)**.
- Local-routing's `message_received`/`llm_input` hooks recognise two transport markers when they strip a turn down to Nick's own words: `"--- Nick's message follows ---"` and `"User message:\n"` (`local-routing.ts:85`, `index.ts` provenance code, `episodic.ts:70-75`). This marker is the contract between the transports and the plugin.

### 2.2 How OpenClaw loads and truncates them

Read from the installed OpenClaw `dist/` (`embedded-agent-helpers-*.js`, `system-prompt-config-*.js`, `workspace-*.js`); behaviour for other OpenClaw versions may differ. I replayed the AGENTS.md trimming function from that file in a scratch script (no OpenClaw process, nothing live touched) — marked **(replayed)** below.

1. **Which files are injected.** OpenClaw's default bootstrap set is `AGENTS.md, SOUL.md, IDENTITY.md, USER.md, TOOLS.md, BOOTSTRAP.md (only while onboarding is pending), MEMORY.md`, plus `HEARTBEAT.md` handled separately. Order in the prompt (`CONTEXT_FILE_ORDER`, `system-prompt-config-*.js:68-76`): AGENTS (10), SOUL (20), IDENTITY (30), USER (40), TOOLS (50), BOOTSTRAP (60), MEMORY (70). **`SELF.md`, `PLAYBOOK.md`, `SCHEDULING.md` are not in that list** — they are "read on demand" (AGENTS.md tells ORION to read `SCHEDULING.md` before scheduling and `PLAYBOOK.md` "only when the request touches its topic") or pushed by the transports (§5.7).
2. **Per-file cap.** `agents.defaults.bootstrapMaxChars` default **20,000**, total cap `bootstrapTotalMaxChars` default **60,000**; neither is set in `openclaw.json`, so the defaults apply (`embedded-agent-helpers-*.js:63-64`).
3. **Generic truncation** (any file over 20,000 chars): 75% head + 25% tail with a marker `[...truncated, read <file> for full content...]` (`BOOTSTRAP_HEAD_RATIO .75`, `TAIL .25`).
4. **AGENTS.md is special-cased** (`trimAgentsBootstrapContent`): when over the cap it keeps **45% head (9,000 chars) + a "policy digest" up to 35% (7,000 chars) + 15% tail (3,000 chars)**. The digest scans the **whole** file, keeps only lines that look like headings, bullets, numbered items or contain words like `must|never|do not|required|security|secret|credential|test|command|commit|push…`, normalises each to ≤240 chars, selects high-priority (`must|never|do not|…`) lines first until the 7,000-char budget is full, and prints them in file order, followed by `[...N more policy lines omitted...]` and `…(truncated AGENTS.md: kept 9000+policy 7000+3000 chars of 31902)…`.
5. **(replayed) What that does to ORION's 31,902-char AGENTS.md:** rendered length 19,188 chars; the head ends at **line 127** of the file (mid-way through the "His day is yours to keep shaped" bullet); the digest is **87 line-fragments** drawn from all over the file, with **73 more omitted**; the tail is the last 3,000 chars = from the `## Safety and communication` section (line 426) to the end (the schedule-edits, focus-session, coding-project and schedule-focus paragraphs). The middle of the file — roughly lines 128-425, i.e. most of the operating contract's scheduling command list, "Added after 2026-10-07", "Action truth", the "Fast router", "Dates", "Memory and Brain", "Capability acquisition" and "Reference router" — is reduced to the digest: sentence fragments such as "`steps` list is never proof of an effect." with no heading context. Whole paragraphs like the "Dates" story and the four-layer "Memory and Brain" list are **not** present as paragraphs.
   - This is the mechanism behind `15f0775`'s note: "AGENTS.md (31k) was cut at 20k so Dates / Memory and Brain / Safety never reached Claude". My replay says that is **only approximately right**: the Safety paragraph does reach (it is the tail), and some Dates/Memory lines reach as digest fragments; what is lost is the paragraph structure and many sentences. Trust the replay's mechanism over the commit message's list; re-run it yourself (§8).
   - Since `15f0775` AGENTS.md begins with a "Look it up" section telling ORION the manual lives in the brain, precisely because the file is cut (`AGENTS.md:8-16`).
6. **Cache.** The workspace files go above OpenClaw's `SYSTEM_PROMPT_CACHE_BOUNDARY` (stable prefix, hashed and cached in-process: `stablePromptPrefixCache`, limit 64); only `HEARTBEAT.md` is "dynamic" (kept below the boundary). Together with Anthropic `cacheRetention: long` (1 hour), an unchanged prefix is a cache read ($0.10/MTok for Haiku per `model-roles.json`) instead of a write ($1.25/MTok). That is why `f17471c` measured moving rules around as **more** expensive: a changed prefix is an uncached write ("an uncached write costs 12x a cached read" — commit body).
7. **`continuation-skip`** (§1.3): in a continuing session OpenClaw may skip re-injecting these files.
8. **Skills block** — a separate `## Skills` section with an `<available_skills>` list (name, description, location, capped at `limits.maxSkillsPromptChars` 7,000) comes from the workspace `skills/` dir; the model reads a `SKILL.md` on demand (`system-prompt-config-*.js:203-212`: "Scan <available_skills>. If one clearly applies, read its SKILL.md at exact <location>… One skill up front max.").

## 3. Skills

- **What it is** — OpenClaw "skills" are folders under `<workspace>/skills/<name>/` with a `SKILL.md` (YAML front-matter `name`, `description`, then Markdown). OpenClaw puts a compact `<available_skills>` index (name, description, file location; capped at `skills.limits.maxSkillsPromptChars` = 7,000) into the system prompt under `## Skills`, with the rule "Scan <available_skills>. If one clearly applies, read its SKILL.md at exact <location>… One skill up front max." (`dist/system-prompt-config-*.js:203-212`). So a skill's **description** is always in the prompt and its **body** is loaded only when the model decides to read it (`orion-skill show <name>` is ORION's allowlisted way). The description therefore works as a trigger, which `writing-your-own-skills` says outright.
- **Where** — repo `plugin/workspace/skills/` (11 directories) = live `~/.openclaw/workspace/skills/` (identical at this snapshot). Related: `~/.openclaw/skill-workshop/{proposals,locks,proposals.json}` (OpenClaw Skill Workshop proposals, used by `orion-skill-learning`), `~/.openclaw/plugin-skills/browser-automation` (a plugin-provided skill), live `skills/.disabled/…` (a moved-aside skill). Bundled OpenClaw skills are toggled in `openclaw.json` `skills.entries` (§1.3: only `apple-notes`, `apple-reminders`, `gog`, `notion` on).
- **Authoring route** — ORION has no `file_write`, so `scripts/orion-skill` (`list | show | write <name> --description … --body … | disable`) is the only way it can write a skill: writes only to `~/.openclaw/workspace/skills/<name>/`, name must match `[a-z0-9][a-z0-9-]*`, keeps `SKILL.md.bak-<ms>` on overwrite, has no delete (`disable` renames to `<dir>.disabled-<date>`) (`scripts/orion-skill:2-43,116,147`). Nick granted this on 2026-09-02 (`writing-your-own-skills`: "Nick granted this on 2026-09-02. Use it."). Commit `5655b0b` 2026-09-02.
- **History (all skills)** — three origins. Swift: `ThinkingPolicy.swift` (same rule; used by `GatewayClient.ask`, `native/Orion/Sources/Orion/GatewayClient.swift:131-133`). Both say "The phone route uses the same rule", so they must be kept in step by hand.
- **How it works** —

```js
// scripts/lib/thinking-policy.mjs:6-26
const VERBS = /\b(get rid of|start|move|shift|push|swap|extend|shorten|resize|cancel|skip|drop|delete|remove|clear|book|schedule|reschedule|add|put|replace|rename|fit|make)\b/gi;
const ANCHORS = /\b(before|after|until|between|at least|ending|ends?|same (end|time|as)|instead|then|so i'?m|right after|directly after)\b/i;
const WHOLE_DAY = /\b(plan|schedule|fill|organi[sz]e|redo|rebuild)\b[^.?!]{0,30}\b(my |the )?(day|today|tomorrow|week|evening|afternoon|morning|rest of)\b/i;
const NARRATIVE = /\b(gonna|going to|i'?ll|i will|want to|wanna)\b.{0,80}\b(then|so i'?m|by \d|until|before|after)\b/i;
export function needsReasoning(text) {
  const said = String(text ?? "");
  if (NARRATIVE.test(said)) return true;
  const verbs = said.match(VERBS) ?? [];
  if (WHOLE_DAY.test(said)) return true;
  if (verbs.length >= 2) return true;
  if (verbs.length >= 1 && ANCHORS.test(said)) return true;
  return said.split(/\s+/).filter(Boolean).length >= 35;
}
export function thinkingLevel(text, { model } = {}) {
  if (String(model ?? "").startsWith("ollama/")) return "off";
  return needsReasoning(text) ? "low" : "off";
}
```

  So: `low` when the message is a narrated plan, a whole-day request, has two or more change verbs, one verb plus an anchor word, or is 35+ words. Local (`ollama/…`) models never think. The Swift app adds a **boost**: if two or more tool calls failed in the last turn (`ThinkingPolicy.struggled`), thinking is `low` for the next 10 minutes (`boostSeconds = 600`, `GatewayClient.swift:94,277-281`, log line `[thinking] tool calls kept failing — thinking on for the next 10 minutes`).
- **Contracts** — Output is exactly one of `off|low`; passed as `openclaw agent --thinking <level>`; `ORION_BRAIN_THINKING` overrides it for a whole run (`orion-remote:810`, used by `orion-eval-schedule`).
- **History** — `9e901a9` 2026-10-07 "think only when it matters; one-call 'after X, ending N before Y'"; `26baa71` 2026-10-08 "more proactive; end/stop mean finish; thinking only for multi-part changes" (narrowed: "he doesn't ALWAYS need thinking").
- **Gotchas** — (1) The verb list contains `start`, `make`, `put`, `add`, so ordinary talk ("let me add that I'm tired and start again") can trip it; false positives cost tokens, false negatives cost accuracy. (2) The front desk's own `tier/think` outputs (`quick+off`, `standard+low`, `deep+high`, prompt text in §5.3) are **not** used for the cloud turn; and Qwen thinking is on/off only anyway (HANDOFF 2026-10-08). (3) `localModelLean` and `think:false` params in `openclaw.json` mean local turns never think regardless.
- **Walk it yourself** — `node -e 'import("/Users/nickmadaio/Desktop/ORION/scripts/lib/thinking-policy.mjs").then(m=>["remind me at 6:55","move gym to 6 and swap study and lunch","plan my day"].forEach(s=>console.log(s, m.thinkingLevel(s))))'`; `grep -n "ThinkingPolicy" native/Orion/Sources/Orion/GatewayClient.swift`.
- **Questions to ask your tutor** — Why is "off" the default for a voice assistant? What is a "boost" and what signal triggers it? Which of the two copies of the rule would you change first and how do you make sure the other one follows?

### 5.7 Context injected by the transports (the third prompt layer)

OpenClaw's prompt (§7) is not the only thing Claude reads: the **user message itself** is wrapped by whoever sends it. `scripts/orion-remote` (phone and Discord) and the Mac app each add facts to the front of Nick's text. This matters because the plugin treats the whole thing as one user turn, so a marker line separates machine text from Nick's words: `--- Nick's message follows ---` (`orion-remote:535`, the last line of `CHANNEL_BRIEF`; consumers: `local-routing.ts:85`, `episodic.ts:70-75`, `approvals.ts:494-498`, `gate.test.ts`).

**Phone/Discord (`scripts/orion-remote`)** — `askBrainOnce` (`:790-826`) writes a temp file `~/.openclaw/orion-controlled/brain-<hex>.txt` (mode 0600; "Via a FILE, never argv. The message is untrusted text") containing, in order:
1. `phoneContext()` (phone only, `:625-684`): "[orion-remote] Live facts for this message (read just now, not from Nick):" then
   - (evals only) `TEST CLOCK` line;
   - `[Scheduling preferences — read before planning]` + the first 12,000 chars of the live `SCHEDULING.md` (`:633`);
   - open apps on the Mac (`doApps`); "ORION's own app is the native Mac app Orion.app. It is not a website: never open a localhost or http address for it. Its tabs are Home, Tasks…, Projects, Health, Finances, Brand and Settings. To show one, run …/orion-show <tab>";
   - `todaySchedule()` (`:554-607`): "Earlier today (already over on the calendar): …", "On the calendar now (HH:MM): …", "Later today: …" each block as `Title 09:00–10:30 [fixed|high|medium|low, movable]`, "His last class ENDS at …", the travel walls ("Travel (not free time, nothing goes here)…"), and the rank legend;
   - `openCheckins()`, `phoneLock()` (runs `orion-phone-time status`), `watchQuestion()`, `recentOutreach()` ("You messaged him first… this message may be his answer.");
   - a long inline guide to `orion-reschedule`/`orion-tasks`/`orion-checkin` (`:650-680`, the fourth copy of those rules).
2. `savedNote` (`:796`): "[orion-remote] Already saved from his message (by the transport, not by you): … Tell him in one short clause that it is saved; do not save it again, and never say 'noted' for anything that is not in this line." — produced by `saveStandingRules` (§6.2) *before* the model runs.
3. `briefFor(sender)` — `CHANNEL_BRIEF` (`:493-537`, preceded by a long explanatory comment from `:446`): "[orion-remote] Context from the transport, not from Nick:" + channel lines (`@discord`/`@phone`), "The remote channel is ALREADY working — you are answering through it right now", the list of words the transport handles itself (`status, pause, resume, cancel, approve, deny, priority, device, apps, files, agent`), the `agent …` verbs, and the **approvals paragraph** ("you CANNOT create an approval id, and you cannot approve one… Never invent an id…"). A comment explains a trap: this brief is recorded as part of Nick's turn, so it **must not contain** words matching the plugin's `AUTHORITY_INSTRUCTION` regex (enable/allow/grant/permission/capability/profile/unlock…), otherwise it would satisfy a security check on every turn; `scripts/orion_v2_remote_check.sh` asserts it (found by independent review, 2026-09-02).
4. then Nick's text.

After the reply: `fixReply` and `lintReply` (rewrite mixed/24-hour times, repeated sentences), and the **truth check** (`askBrain`, `:723-752`, notes at `:686-690`): if the reply claims something was done with `tools === 0`, or claims an inability without looking, the turn is re-asked **once** in the same session with one of three fixed notes — `CHECK_DONE` "Your last reply says something was done, but no tool ran in that turn, so nothing happened…", `CHECK_CANT` "Your last reply says you can't do that, but you did not look. Check TOOLS.md or use tool_search…", `CHECK_SILENT` — on `ORION_ESCALATION_MODEL` (default `anthropic/claude-sonnet-5`; "off" disables). Rationale in the code comment: Haiku is the everyday brain ("a week of real use including every scenario run cost about $1.60"), and the retry is rare so a stronger model there is cheap.

**Mac app (`native/Orion/Sources/Orion/GatewayClient.swift`)** — `ask()` builds `--message = recentOutreach() + SchedulingMemory.context(for: text) + text` (`:125`). So the Mac app adds only (a) the "[ORION context: you messaged him first — … This message may be his answer.]" line (`:100-111`), and (b) `SCHEDULING.md` (first 12,000 chars, labelled "[ORION scheduling preferences — consult with current calendar and Orion to-dos]" … "[Current user request]") **only when** the text matches `\b(schedule|scheduling|plan|planning|reschedule|class|lecture|nap|commute)\b` (`SchedulingMemory.swift:4-12`). No live facts, no `todaySchedule()`, no command guide: the Mac app route leans on AGENTS.md (digested, §2.2) and on tool outputs. This asymmetry between the two routes is the single most important thing to know when debugging "it worked on the phone but not at the Mac" **(inferred from the two code paths; not measured)**.

- **Gotchas** — (1) Anything the transport prepends can leak into episodic memory: `episodic.ts:64-75` `nickWords()` exists because "Capturing the whole turn wrote those rules into his journal as if he had said them (found 2026-09-29: 'It is not a website: never open a…')". (2) Because `SCHEDULING.md` is sent on every phone turn (12k chars ~ 3k tokens) regardless of topic, it inflates cost on every phone message and sits *after* the cached prefix, so it is billed uncached **(inferred from OpenClaw's cache boundary, §2.2)**.

### 6.1 Workspace `MEMORY.md` and `USER.md` (store 1)

Covered in §2.6/§2.10. Memory view: `MEMORY.md` = lessons about ORION, `USER.md` = facts about Nick. Both are loaded whole into every Claude turn (they are under the 20k cap), so **anything appended there costs tokens on every call** — `orion-remember:19-22`: "Use --user only for durable facts about Nick that will still be true in six months, because that file is loaded into every session's startup context."

### 6.2 `orion-remember`, `orion-recall`, standing rules

- **`scripts/orion-remember`** — "The one way Orion is allowed to write a memory" (header; exists because the `coding` tools profile strips `file_write`, ORION improvised a `cat >> … <<EOF`, that missed the exec allowlist, and "hung the session for the full four-minute agent timeout", 2026-08-09). Two modes: `orion-remember "text"` → `~/.openclaw/workspace/memory/<today>.md` under `## Noted` as `- HH:MM — text`; `orion-remember --user "text"` → appends `- YYYY-MM-DD — text` to **live** `USER.md` (`:107-113`). Limits: 600 chars (`MAX_LENGTH`, `:31`), control characters stripped (so a note cannot forge headings), credential-shaped strings refused (`SECRET_SHAPED`, `:65-69`: `sk-…`, `ghp_…`, `xox…`, `AKIA…`, JWT). Notes go inside `## Noted`, outside the `orion-daily` marker block, so the nightly rewrite does not destroy them (`:82-90`). Binary-looking source: use `grep -a` on this file.
- **`scripts/orion-recall`** — "The one way Orion is allowed to look something up in his own memory" (header). Runs `~/.openclaw/bin/openclaw memory search --max-results 12 <query>` (20 with `--all`), parses `<score> <file>:<lines>` headers (the path regex is `.+?` because vault paths contain spaces — a one-character bug once made every vault hit disappear, `:66-79`), drops probe/doctor/cron/mission session hits unless the query mentions them (`SESSION_NOISE`), strips YAML frontmatter, prints the best hit's first 8 body lines (`--all`: all hits, 40 lines). A miss prints `nothing in memory about "…"`; a failure prints `search failed — <stderr>` and exits 1 (so "I searched and found nothing" differs from "I could not search", `AGENTS.md:389-392`).
- **`saveStandingRules`** (`scripts/orion-remote:754-789`, rules in `scripts/lib/remote/standing-rules.mjs`) — runs **before** the model, on Nick's own words: "naps at least an hour and 15 ALWAYS" / "going forward…" become (a) a scheduling minimum via `setMinimum` (`life-config.json`, enforced by the planner), (b) a line in the Brain note `20 Areas/Me/Learned about Nick.md` (`- [rule] … (said date)`), and (c) `orion-remember --user "Standing rule (date, his words): …"`. The model is then told via `savedNote` that it is already saved (§5.7). In eval mode nothing is written ("evaluation run: not written"). Origin: 2026-10-01, "'naps at least an hour and 15 ALWAYS' and 'going forward…' both got 'Noted' and neither was saved".
- **History** — `orion-remember`/`orion-recall` in the first tracked commit `93e9a42` (2026-08-20; written 2026-08-09); `orion-recall` frontmatter strip and path-with-spaces fix `52462f4` 2026-09-02 / around Aug 12 **(inferred from comments)**; `saveStandingRules` `3034d64` 2026-10-01.
- **Gotchas** — `orion-remember --user` writes only the **live** USER.md; a later `orion_v2_workspace_sync.sh --apply` would overwrite it (a backup is made). The skill `when-nick-tells-you-something` calls it "the only sanctioned memory write" though `orion-brain learn` also exists.

### 6.3 Episodic capture and the daily journal (store 2)

- **What it is** — A deterministic, zero-model-token filter that appends Nick's preferences, corrections and decisions to `~/.openclaw/workspace/memory/YYYY-MM-DD.md` at the end of every turn.
- **Where** — `plugin/orion-control/src/episodic.ts` (146 lines); hook `before_agent_finalize` at `plugin/orion-control/src/index.ts:1688-1717`, enabled by `enableEpisodicCapture: true` (manifest `openclaw.plugin.json:135`). Skips sessions whose key/trigger matches `cron|heartbeat|doctor|test|subagent|eval` (`index.ts:1693-1695`; "2026-09-29's 60-scenario run filed its questions as Nick's own").
- **How it works** — `readLatestUserTurn` (transcript) → `nickWords()` cuts everything before `--- Nick's message follows ---` and drops `[orion-remote…]` lines (`episodic.ts:70-75`) → `episodeFromUserText()` (`:77-103`) splits into sentences, skips questions (unless they say "remember/don't forget/before I forget/from now on/going forward"), keeps sentences matching `DURABLE_SIGNAL` (`remember`, `from now on`, `always`, `never`, `prefer…`, `don't like`, `should`, `must`, `we decided/agreed/chose`, `actually`, `instead of`, "that's wrong"…) or `DURABLE_PERSONAL_FACT` (`my browser|email|phone|timezone|… is`), rejects secret-shaped text (`SECRET_SHAPED` incl. `password`, `api key`, `verification code`), max 4 sentences / 600 chars → `appendEpisode()` (`:111-146`) writes `- HH:MM — [auto] <text>` under `## Episodes` (created above the `orion-daily:begin` marker), de-duplicating by normalised text, file mode 0600.

```ts
// plugin/orion-control/src/episodic.ts:129-130
const line = `- ${clock} — [auto] ${compact}`;
const heading = "## Episodes";
```

- **Format of a daily file** — `# YYYY-MM-DD`, optional `## Noted` (from `orion-remember`), `## Episodes` (`[auto]` lines), then the generated block between `<!-- orion-daily:begin … -->` and `<!-- orion-daily:end -->` (§6.4). 39 files, 2026-07-30 → 2026-10-13, live only (not in git).
- **Readers** — OpenClaw memory search (indexed), `orion-recall`, `orion-brain-seed` ("the daily memory files" are a seed source; daily brain notes link every entity). Never loaded whole into a prompt ("Today and yesterday by name" was the original OpenClaw expectation, `orion-daily:7-10`; this OpenClaw build's bootstrap list does not include `memory/`, §2.2).
- **History** — `5e29292` 2026-09-30 "supplement edit/remove, episodic memory and task catalog updates" (the plugin hook); `71d4581` 2026-08-11 (daily file dating bug: UTC vs local day).
- **Gotchas** — The regex is intentionally over-inclusive ("`should`", "`always`" capture project chatter): "It intentionally over-captures a few project decisions into the daily journal; the later consolidation pass decides what deserves long-term promotion" (`episodic.ts:57-62`) — that consolidation pass is not automated. The write is local-day (`en-CA`), so it follows Nick to London.

### 6.4 `orion-daily`, the nightly pipeline, `orion-learn`
