## HIGH

1. Floating pill claims a live focus session that does not exist.
   `orion-ui-d.png` and `orion-ui-d2.png` show "FOCUS . BLOCK 1 OF 1, the resume, 24:57" with a pause button.
   `orion-session status` says "Session abandoned, 2s of focus". The log has the last session start at 03:08:38 and nothing after.
   The clock stayed at 24:57 for the whole audit, about 22 minutes after that start.
   Cause: `SessionFloatController.swift:25-26`. `update(minimized:)` runs only when `sessionMinimized` changes (the sink at line ~20). When the session ends, the pill is never re-evaluated.
   A second gap: `hasLiveSession` is true for `.paused` and `.waitingForReturn`, and `phaseRemainingSeconds` stops moving when status is not `.running` (`SessionTabModel.swift:238-249`), so a stale `.waitingForReturn` freezes the clock.
   Fix: have the controller also subscribe to `state.sessionTabModel.$snapshot` (or a published `hasLiveSession`), `.combineLatest` with `$sessionMinimized`, and call `update` on every change.
   Also show the state on the pill: when not `.running`, replace the time with "paused" or "waiting for you" in dim type, and fade the ring to a hairline.

2. Orphaned guard-setup sheet for a session that is gone (`orion-ui-a.png`).
   The window is off screen but alive, with "Select at least one work app" and ARM GUARD disabled.
   `SessionTabModel.swift:477-480` clears `guardSetupRequest` only when `snapshot.session` is non-nil. When the session is abandoned or finished, `evaluateGuardSetup()` returns at `guard let session` and the request lingers.
   Fix: put `guardSetupRequest = nil` in the `guard let session = snapshot.session else { ... }` branch. Make `presentProactiveGuardIfNeeded` (`FocusSessionHome.swift:743`) check the session is live before presenting.

3. Timer.publish stored on a View struct (the known trap). All at risk:
   - `DashboardView.swift:89` `briefTicks` (30 s). It drives `dayModel.refresh`, agenda and reminders refresh, the brief, and `refreshEarlyContext` (line 203). The view is re-created whenever its parent re-renders, which means more often than every 30 s if the parent has a 1 s source. If it is starved, the agenda and brief go stale silently.
     Fix: `@StateObject private var briefTicker = RefreshTicker(interval: 30)` and `.onReceive(briefTicker.$tick)`.
   - `SharedChatView.swift:10` creates `Timer.publish(every: 4)` inline in `body`, so it is rebuilt on every evaluation and the chat list can stop refreshing while the composer or phase is changing.
     Fix: `@StateObject private var ticker = RefreshTicker(interval: 4)` and `.onReceive(ticker.$tick) { _ in state.refreshChats() }`.
   Not at risk:
   - `SessionTabModel.swift:154` is on a model object that lives for the app's lifetime.
   - `ApprovalsOverlay.swift:125` and every `Timer.scheduledTimer` hit in the grep are owned by model objects.
   - `FocusSessionHome.swift:1243` already uses RefreshTicker.
   - `phoneTicker` (`DashboardView.swift:245`) is an ObservableObject, which is correct.

## MEDIUM

4. Blank grey floating window (`orion-ui-b.png`).
   692x769 at layer 101, opaque `#282828`, no content, sitting at (1487, 404). It looks like a panel whose SwiftUI content is empty or failed to render, or a leftover.
   It is on-screen-ineligible now but would cover a large area if shown. I could not tie it to a source file: the `grep` for level 101 found nothing. Needs a look at `PanelController`/`Console.swift` (level `.floating` is 3, so this is something else).
   Fix: give any empty-state panel `orderOut` on empty, or draw an explicit "nothing here" line instead of a filled shape.

5. Timeline card is clipped at the top (`orion-ui-main.png`).
   The right-hand day card starts under the nav scrim: no rounded top edge, no date header, the "ALL DAY" row is jammed against the tab underline. The card's top border and the header at `DayTimeline.swift` `header` are hidden behind the nav.
   Fix: add `.padding(.top, 12)` below the nav on that column, or move the scrim into `safeAreaInset(edge: .top)` so the column starts below it.

6. Timeline cannot show "now".
   It is 03:30 and the grid is scrolled to 6 AM, so the now-line (`DayTimeline.swift:284`) is off the viewport and nothing explains it. Only the Wake 9:00 AM marker is visible.
   The 3:30-5:00 PM ECON1115 block ends exactly at the bottom edge of the card, so the end of the day looks cut off.
   Fix: when now is outside the scroll window, draw a small hairline label "now 3:30 AM, up" at the viewport edge, and let `lastHour` rows run to 6 PM.

7. Boxiness against Nick's taste (`orion-ui-main.png`, `orion-ui-a.png`).
   - Plan tab: three rounded filled cards (ORION'S PLAN, composer, to-do list) plus a fourth for the timeline. Equal-width left column, filled with `Color.white.opacity(0.03-0.05)`.
   - Tag chips (`internship`, `misc`, `school`, `medium`, `high`) are solid coloured pills, five per row, and the purple "only schedule this once..." note is a filled pill.
   - The to-do tabs, the green "keep on going. lock in." banner and the filled checkbox squares add more fills.
   - Guard sheet: every app is a filled card with a different width (`FocusSessionHome.swift:1163` `RoundedRectangle(cornerRadius: 9).fill(white 0.035)`), centred in a column and cut mid-row ("Ollama") by the 300 pt max height. ARM GUARD is `.borderedProminent`, a filled button. The mode picker is five filled tiles of equal width.
   Fix: replace `.background(RoundedRectangle...fill(...))` with a 0.5 pt `Rectangle().fill(LinearGradient(colors: [.clear, .white.opacity(0.14), .clear], startPoint: .leading, endPoint: .trailing)).frame(height: 0.5)` between rows. Render tags as plain mono text with a dot (`Text("internship").foregroundStyle(tagColor)`), no fill. Make the plan column about 0.42 of the width and the timeline about 0.58 with a hairline between them. Give ARM GUARD `.buttonStyle(OutlineButton)` (stroke cyan 0.6, no fill). Left-align the app list, with a hairline under each, and let it grow instead of capping at 300.

8. Material and blur that contradict the "real alpha" rule.
   - `FocusSessionHome.swift:1314` and `SessionFloatController.swift:122`: `.background(.ultraThinMaterial, in: Capsule())` on the pill. In `orion-ui-d.png` it renders as an opaque grey slab, not see-through.
   - `PanelView.swift:51`: `.ultraThinMaterial` on the reach message bubble (also a "bubble").
   - `VisualEffectBackground.swift:38` (hudWindow) and `MorningScreen.swift:70` (NSVisualEffectView).
   - Decorative `.blur` at `BreakSanctuary.swift:206`, `FocusSessionHome.swift:1001`, `ProjectRunConsole.swift:113` are glows, which is acceptable.
   Fix: pill background `Capsule().fill(Color.black.opacity(0.35))` with a `strokeBorder(.white.opacity(0.14))`, or drop the capsule fill and keep only the hairline. Reach bubble: text only with a left hairline.

9. Summon window shows a flat, harsh orb (`orion-ui-c.png`).
   The saturated stacked rings (pure red, yellow, olive) look like a palette-quantised render and clash with the cyan/dark system everywhere else.
   The "Reply to ORION" field has a hard black rectangle inside a rounded capsule, with a visible edge, and the placeholder is low contrast (about 2:1).
   Fix: `TextField(...).textFieldStyle(.plain).background(.clear)`, placeholder at `white.opacity(0.5)`. Check the render path for banding (use `.interpolation(.high)` or a Canvas gradient).

10. Disabled/placeholder contrast.
    Header badges "0", "0", "16/22", "3" have no labels. The status text "Service connected" and the clock sit in dim grey. The tab icons are 11 pt grey. Nav labels use about `white.opacity(0.55)`.
    ARM GUARD disabled state is grey on grey (`orion-ui-a.png`).
    Fix: raise dim text to at least `white.opacity(0.62)` (about 4.5:1 on `#02030a`); label the badges with a `.help` and a tiny mono caption.

## LOW

11. Fonts mix: mono (`OrionTheme.mono`) for headings and the to-do title ("to-do list" in a heavy mono at about 17 pt), SF Rounded for the pill ring, SF for body, uppercase tracked mono for labels. The to-do title is the only lowercase mono heading; others are caps. Standardise: mono caps for labels, SF for content, one numeral face.
12. Pill ring is a gradient stroke with a fat 3 pt weight and round cap, and the thumb is a blob at 12 o'clock (`orion-ui-d.png`). Use a 1.5 pt hairline ring and a single large number, as with the other meters.
13. Colour: cyan for focus, orange for warnings and the Wake line (dashed orange across the full width), plus green, purple, blue and amber tags and event blocks. Event blocks are fully filled green and orange rectangles. Use a 2 pt left bar and a text colour only.
14. Empty states without an explanation: the Plan tab shows no "nothing scheduled before 1:30 PM" note; the day has events only after 13:30.
15. Agenda vs app: I could not cross-check events against Calendar without opening it. The log shows 73-74 events in window across 12 calendars, and the main window shows 2 timed events plus an all-day "Macro (ECON1115) Quiz 1". The pill's "REST OF TODAY" strip (`FocusSessionHome.swift:1243`) reads the calendar directly and is a second source of truth; it uses `RefreshTicker` correctly. The greeting "Up late" is accurate for 03:30.
16. `SessionDayStrip` renders `let now = Date()` inside `ForEach`, so "current" is correct only when the ticker fires (60 s). Fine, minor.
17. Truncation: pill title uses `.frame(width: 150)` plus `lineLimit(1)` (`SessionFloatController.swift:~76`) so a long task name is cut with no tooltip; media title is also 120 pt wide.
