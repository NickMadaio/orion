Day-zero corrections to the handoff:

- `TOOLS.md` in the live workspace is regenerated by the runtime (90 allowlisted
  commands); the repo copy is a 2026-09-02 snapshot (48). Prompts in this campaign
  use the live file.
- `MaxCapacity` from `ioreg -rn AppleSmartBattery` is a **percentage** on this Mac.
  Battery capacity in mAh is `AppleRawMaxCapacity` (7,910 at day zero; design
  8,579). §10.4's %/hour formula uses that.
- **Energy method changed (A4).** The `AppleSmartBattery` registry publishes about
  once a minute, so §10.4's 1 Hz per-task sampling is impossible. Its
  `PowerTelemetryData` accumulators (`AccumulatedSystemLoad` / count, mW) give the
  exact average load between published snapshots. Energy is therefore measured in
  windows: ≥2 minutes idle, then tasks back to back for ≥4 minutes; joules per task
  = (busy W − idle W) × seconds ÷ tasks. Verified unplugged on 2026-10-08: idle
  1.26 W (114 s), llama3.2:3b load 13.4 W (120 s, 14 requests).
- `orion-eval-schedule` records the *requested* thinking level ("default"), not
  the level ORION applied (its ThinkingPolicy chose `off` in the day-zero run).
  The V3 runner records the applied level. The old harness also leaves
  `eval-reschedule-undo.json` behind after a run.

### 2.2 Thinking: what actually reaches the model (measured)

- **OpenClaw → Ollama mapping** (`dist/stream-*.js`): `off`→`think:false`;
  `minimal`→`"low"`; `low|medium|high`→the same string; `xhigh|adaptive|max`→`"high"`.
  Forwarded only when the model's config does not say `reasoning:false`
  (qwen3.5:9b is `reasoning:true` in `openclaw.json`).
- **Ollama 0.34.4 with a level string on Qwen** (`thinking.values` `[false,true]`):
  the docs say unsupported names use the model default. Measured on qwen3.5:9b,
  temperature 0, two repeats each: `true`, `"low"`, `"medium"` and `"high"` all
  produced the **identical** 1,764-character thought (724 output tokens, ~15.5 s);
  `false` produced 11 tokens in 0.2 s warm. **Through ORION, Qwen thinking is
  on/off only.** "Low" for Qwen exists only as the §7.2 approximations.
- **Thinking in history:** the Qwen3.5 card says earlier turns' thinking must be
  dropped. Ollama's `qwen3.5` renderer (also used by qwen3.6:27b) does this, and keeps
  thinking inside the current tool loop when `think:true` — measured by
  `prompt_eval_count`: earlier-turn thinking added 0 tokens; current-loop thinking
  added ~400 with think on and 0 with think off. The harness can pass thinking back
  as Ollama's docs suggest.
- **Qwen3.6 `preserve_thinking`:** documented on the card as a chat-template
  argument (`chat_template_kwargs`). Ollama's thinking docs do not mention it and
  the model uses the shared `qwen3.5` renderer. Treated as **not exposed**; the
  Phase 3 smoke test confirms.
- **Sampling defaults:** Ollama's Modelfile for both Qwen models sets the
  **thinking** preset (temperature 1, top_p 0.95, top_k 20, presence 1.5). ORION's
  think-off turns therefore run with thinking-mode sampling, not the card's
  non-thinking preset (0.7 / 0.8). That is variant S2's first test.

### 2.3 Benchmark methodology that becomes ORION graders

- **BFCL relevance detection** ([BFCL blog](https://gorilla.cs.berkeley.edu/blogs/8_berkeley_function_calling_leaderboard.html)):
  the functions offered don't fit the request; the expected output is *no call*.
  Argument checks accept a *list of acceptable values* per parameter, ignore
  case and whitespace in strings, and let optional parameters be omitted. → J1/J2
  graders use acceptable sets per argument, not one exact string; J1 has
  should-not-call cases.
- **BFCL V3 multi-turn** ([BFCL V3](https://gorilla.cs.berkeley.edu/blogs/13_bfcl_v3_multi_turn.html)):
  "missing parameters" expects the model to ask rather than assume; a turn ends when
  the model makes no call. Grading is **state-based** (backend state after each turn)
  **plus response-based** (the minimal required calls appear as a subset; extra or
  re-ordered calls allowed). BFCL does not specify how the clarifying question's
  content is scored. → J3/J6 grade end state; J2 checks that required calls appear
  (subset), without penalising harmless extra reads; ask-cases are graded on "asked
  and made no change".
- **"Missing functions"** (no available tool fits) is BFCL's version of ORION's tool
  gap: the right outcome is an honest refusal, which is how §5.4 treats gaps.

### 2.4 Tool-prompt format

- **Qwen** ([function calling](https://qwen.readthedocs.io/en/latest/framework/function_call.html)):
  Hermes-style tool use, carried by the chat template; JSON Schema with `required`
  and `enum`; formats in parameter descriptions ("HH:MM"); put context such as the
  current date in the messages; avoid stop-word (ReAct) templates with reasoning
  models; output does not always follow the protocol, so handle malformed calls.
  Qwen3.5 cards name the `qwen3_coder` tool parser for vLLM/SGLang. Through Ollama
  the `qwen3.5` renderer/parser handles this, so the harness uses native `tools`.
  → T2 schemas use `enum` and format strings; the runner counts malformed calls as
  failures, never retries silently.
- **gpt-oss** ([card](https://huggingface.co/openai/gpt-oss-20b)): native low/medium/high
  reasoning (Ollama `think` level); must use the harmony format (Ollama's template
  does); no recommended sampling or history guidance on the card.

- **Sources:** 886 session files → 151 real; excluded 509 eval-keyed, 110 probe-opened,
  48 scenario/audit replays, 68 scripted replays (keyless reset sessions only). Real keyed
  sessions are never dropped whole; only their probe turns are.
- **Turns:** 600 unique real turns, 2026-07-29 → 2026-10-08.
- **Last 30 days:** 315 turns on 14 active days. Median 11 turns per active day, 2 per active hour
  (p90 12). 62% voice, 20% Mac typed, 18% phone. 14% of turns get `NO_REPLY` (mostly speech not
  addressed to ORION). Reply latency p50 2.3 s, p90 10.5 s (Haiku). Tool turns use a median of
  2 calls (p90 6).
- **Jobs (last 30 days):** schedule 32, focus 27, phone-lock 21, time 16, app 13, health 11,
  reminder 10, chat 9, media 7, weather 5, todo 5, brain 5, lights 1, other 155. "Other" is
  mostly fragments, follow-ups and talk about ORION itself; read, not trusted.
- **Failure catalogue:** 26 entries. Of the 13 handoff seeds: 9 confirmed in real logs, 1 from
  an eval run only (wake 7:30), 1 not in ORION logs, 2 not found.
- **What the logs add to the plan:**
  1. False claims happen without any tool call and across turns (the 2026-10-08 "Done" came in a
     turn with no tool). The claim checker must use the whole conversation's tool results and
     recognise claims without a "done" verb ("you're clear", "already booked").
  2. "Note that for later" never recorded anything (8 turns on 2026-10-06). J5's repair-queue
     cases are a real gap, not a nicety.
  3. The silent llama3.2:3b fallback looped on the repeat guard and spoke raw tool JSON. Local
     tool calling through the production route is the first thing to test.
  4. `orion_task_run` results put 4 KB of tool metadata before the outcome; graders must parse
     the outcome fields.
  5. Sessions with a known key that were really coding probes still exist before September;
     they are outside the 30-day window that drives test weights.
