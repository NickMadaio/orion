# Procedural Memory and Skill Learning

A skill stores a reusable method after evidence shows the method is durable.
It should not absorb every successful action or one-off preference.

Part official documentation, part Orion's own synthesis. Treat the reasoning as unverified.

## Learning test

Create or revise a skill only when:

- the workflow is repeated or explicitly requested,
- representative outcomes are verified,
- triggers and boundaries can be stated clearly,
- secrets and unnecessary personal data are excluded,
- the procedure can be tested without expanding authority.

## Governed lifecycle

Gather evidence → design narrowly → create a pending proposal → inspect and
scan → test positive and adversarial cases → version and hash-bind → approve
and apply → observe use → propose later revisions.

Knowledge notes may explain *why*. Skills should stay concise and teach *how*.
Neither can self-grant tools, permissions, credentials, budget, or approval.
