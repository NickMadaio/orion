## Behavior

Each authority check calls the existing orion-authority show --json with fixed
arguments, bounded time and output. It requires the installed plugin catalog,
known resolved mode, file-backed profile, supported exec policy and unambiguous
enabled automation tier. Candidate fallback catalogs and CLI overrides refuse.
Only exact agenda_today arguments are supported. Standing routines and daily
rollup remain unsupported even if a source diagnostic labels them AUTO. Command
paths must match this checkout; approval, notification, escape-hatch or differing
subcommand classifications do not grant eligibility.

Native focus comes from the app's read-only orion-session status --json route,
using this host's socket. No reducer is reconstructed from stored lifecycle
events. Running, paused and break sessions stay protected. Unknown or unreadable
native status is never interpreted as inactive. Legacy focus.json is also checked:
an active session from either source protects focus; both must be known inactive
to report false. Missing legacy state is inactive; corrupt legacy state is unknown.

The adapter provides no execution, notification or installation method. The
authority CLI's source classification is diagnostic; a future production executor
must bind human-installed policy and recheck authority at the effect boundary.
The current check must not be represented as consuming an approval or granting
permission to an arbitrary caller. Checking mode earlier is not atomic with a
later effect. Those are next implementation gates.
